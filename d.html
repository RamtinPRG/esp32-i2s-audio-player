ESP Audio Player — Refactored Architecture

Event-driven, layered, single-owner state. Every cross-module interaction is an event on the bus.

1Layered Architecture

Arrows between layers show dependency direction. Services never call each other; UI never calls services.

app / orchestration services (feature owners) ui (passive views) bsp (hardware wrappers)
App Layer orchestration only — owns mode transitions
app_core
FSM task. Handles boot → player → transfer transitions. Only module that changes mode.
app_events
Central pub/sub bus. Typed events, value payloads, no pointers.
app_state
Single owner of mode, boot selection, volume, mute. Snapshot API.
Service Layer feature owners — publish events, subscribe to events, never call each other
input_service
Knob + button edges → EVT_INPUT_*.
playlist_service
SD scan, cursor, next/prev. No audio knowledge.
audio_service
SD → I2S pipeline. Owns PCM read task and DMA writer.
cover_service
Lazy BMP decode, small LRU, prefetch next track.
transfer_service
Wi-Fi AP + HTTP upload + mDNS. Publishes upload progress.
UI Layer passive views — render state, never mutate app state
ui_router
Show / hide screens.
ui_boot_screen
Player / Upload menu.
ui_player_screen
Cover, title, elapsed, EQ bars.
ui_transfer_screen
SSID, URL, progress bar.
ui_volume_overlay
Volume bar + mute icon.
ui_theme
Colors, fonts, sizes.
BSP Layer thin hardware wrappers — no logic
bsp_display
ST7789 + LVGL port init.
bsp_sdcard
SPI bus + FATFS mount.
bsp_audio_out
I2S TX channel init.

6Hard Ownership Rules

These constraints are what keep the architecture from rotting back into a ball of mud.

1Only bsp_* touches hardware pins and registers.
2Only ui_* calls lvgl_port_lock and LVGL APIs.
3Only app_state owns mutable app-level state.
4Only app_core performs mode transitions.
5Only audio_service writes to I2S and reads PCM from SD.
6services/* never #include "ui.h".
7ui/* never includes any service header.
8Cross-module = events only. Direct calls only for app_core → service_start/stop.
9Event payloads are value types. No pointers into caller memory.
10Blocking init (SD, Wi-Fi) runs in a transition worker, never in the FSM task.

7Folder Layout

Mirrors the layers. Any file in services/ can be tested without LVGL or hardware.

8Incremental Migration Plan

Each phase compiles and runs. Stop at any phase — even 1–3 removes most of the coupling.

P1Add app_state. Move volume, mute, mode, selection. Delete app_mode_get_*_ptr().
P2Add app_events. input_service publishes only. Mode logic moves to app_core.
P3UI subscribes to events. Remove ui_* calls from audio, http, input.
P4Split modules into services/. Rename to service naming.
P5Split ui.c into per-screen files + router + theme.
P6Lazy cover loading via cover_service LRU + prefetch next.
P7Move blocking transitions into a transition worker task.
