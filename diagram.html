ⓘ Reading the diagrams

Two hubs app_mode.c owns the mode state machine and orchestrates every service, while ui.c is the shared presentation sink that almost every module writes to.
Audio is a two-task pipeline sd_read_task never touches I2S; i2s_write_task never touches the SD card. They hand off through audio_data_queue and recycle buffers via free_buffer_queue.
Transfer mode is fully torn down When leaving Upload mode, wifi_transfer_stop() deinits the Wi-Fi driver and mDNS so the memory goes back to the audio path and cover-art PSRAM.
UI calls are the weak seam Four different tasks call into ui.c directly and block on the LVGL mutex. Moving these to a UI event queue would decouple the diagram considerably.
